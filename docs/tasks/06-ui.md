## Phase 1 — Review thread (Day 2)
### Tasks
- [x] Thread view: messages, composer with file upload, "agent is working" state with collapsible tool steps (no streaming)
- [x] Cards: field (value + quote + clause), flag, rule, unitMatch, summary; workOrder read-only. Condition/equipment and workOrder actions come with task 05
- [x] Card actions inline (accept / reject / edit / choose); resolved cards show their state
- [x] Confirm bar: open items count, Confirm, override reason when needed
### Results
- Written by agy and reviewed by Claude. No new dependencies: React 19, plain CSS, a hash router (`#/`, `#/c/<id>`), and `utils/api.ts` parsing every response with the shared schemas.
- **`LeaseThreadPage`:**
  - `GET /conversations/:id` is the single source of truth, refetched after every POST.
  - It polls every 3 s while `analysisStatus` is pending and shows "Full review running…".
  - Errors appear in a dismissible alert, listing `details.pending` and `details.failures`.
  - A typed message shows straight away as a pending bubble, with "Agent is working… Ns".
- **Components:**
  - The upload drop zone shows step progress, and stays available until a lease exists, so a failed extraction can be retried.
  - A message shows its agent steps in a collapsible section (`agentRun`: steps, model, tokens, time).
  - Only the latest assistant message's cards can be acted on; older cards are read-only. Cards read live state from the lease.
  - "All fields" panel: all 20 fields with Edit, the way to change a field after Accept all.
  - Confirm bar: open items, and an override reason when a high-severity rule fails.
- **API:** `GET /conversations/:id` now also returns `review: {pending, highSeverityFailures}`.
- **Review history (owner request):** `GET /api/conversations?kind=lease` returns summaries: file name, unit, lease status, analysis status, open items and last activity. A new message now updates the conversation's `updated_at`. Conversations with no document are left out. The start page lists the reviews newest first, and each row links to its thread. It does one lookup per conversation, which needs a join at scale.
- **Browser test (lease-05, real models):** upload, Accept all, a typed rent correction (27 s, 3 steps, conflict resolved) and choosing a unit (R7 FAIL → PASS). Fixed after the test: the composer placeholder, a one-line confirm bar, a unit picker over all units when there are no suggestions, no Accept on empty fields, older cards collapsed, scrolling to the start of the newest reply, and one "Agent is working" line.
- **Tests:** router, formatters and field helpers. 314 pass and typecheck is clean. The UI itself is checked by hand; the browser extension wasn't connected, so this phase has no screenshot pass.
