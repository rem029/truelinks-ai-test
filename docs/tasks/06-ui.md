## Phase 1 — Review thread (Day 2)
### Tasks
- [x] Thread view: messages, composer with file upload, "agent is working" state with collapsible tool steps (no streaming)
- [x] Cards: field (value + quote + clause), flag, rule, unitMatch, summary; workOrder read-only. Condition/equipment and workOrder actions come with task 05
- [x] Card actions inline (accept / reject / edit / choose); resolved cards show their state
- [x] Confirm bar: open items count, Confirm, override reason when needed
### Results
- Written by agy and reviewed by Claude. No new dependencies: React 19, plain CSS, a hash router (`#/`, `#/c/<id>`), and `utils/api.ts` parsing every response with the shared schemas.
- **`LeaseThreadPage`:**
  - `GET /conversations/:id` is the single source of truth, refetched after every POST.
  - It polls every 3 s while `analysisStatus` is pending and shows "Full review running…".
  - Errors appear in a dismissible alert, listing `details.pending` and `details.failures`.
  - A typed message shows straight away as a pending bubble, with "Agent is working… Ns".
- **Components:**
  - The upload drop zone shows step progress, and stays available until a lease exists, so a failed extraction can be retried.
  - A message shows its agent steps in a collapsible section (`agentRun`: steps, model, tokens, time).
  - Only the latest assistant message's cards can be acted on; older cards are read-only. Cards read live state from the lease.
  - "All fields" panel: all 20 fields with Edit, the way to change a field after Accept all.
  - Confirm bar: open items, and an override reason when a high-severity rule fails.
- **API:** `GET /conversations/:id` now also returns `review: {pending, highSeverityFailures}`.
- **Review history (owner request):** `GET /api/conversations?kind=lease` returns summaries: file name, unit, lease status, analysis status, open items and last activity. A new message now updates the conversation's `updated_at`. Conversations with no document are left out. The start page lists the reviews newest first, and each row links to its thread. It does one lookup per conversation, which needs a join at scale.
- **Browser test (lease-05, real models):** upload, Accept all, a typed rent correction (27 s, 3 steps, conflict resolved) and choosing a unit (R7 FAIL → PASS). Fixed after the test: the composer placeholder, a one-line confirm bar, a unit picker over all units when there are no suggestions, no Accept on empty fields, older cards collapsed, scrolling to the start of the newest reply, and one "Agent is working" line.
- **Tests:** router, formatters and field helpers. 314 pass and typecheck is clean. The UI itself is checked by hand; the browser extension wasn't connected, so this phase has no screenshot pass.
- **Owner feedback after testing (Oct 5):**
  - The latest summary card is now the one place for details: "Fields: n/20 found", "Rules: …" and "n open flags" expand into the field list (`FieldList`, with inline Edit), the rule results (`RuleResultList`) and the open flags (`OpenFlagList`). The separate "All fields" panel is gone. Older summary cards keep their text as a snapshot.
  - "Accept all (N)": the API sends `acceptAllCount` (a test checks it equals what Accept all would accept), and the button is disabled with "Nothing left to accept" at 0. "1 field looks fine" is now singular.
  - Light/dark switch at the top right (`ThemeToggle`, `utils/theme.ts`). It follows the system until clicked, then stores the choice; a small script in `index.html` applies it before the first paint. The dark tokens apply under `prefers-color-scheme` unless `data-theme="light"`, or whenever `data-theme="dark"`.
  - A first version of the rules list showed rule names agy had invented; it now shows only what `RuleResult` holds (ID, severity, status, reason).
  - Not checked in the browser yet (extension disconnected).
## Phase 2 — Units (Day 3)
Owner's direction (Oct 5): organise everything by unit, laid out like a chat app with a left sidebar. Unit and overall dashboards come later.
### Design
- **Sidebar (left, every screen):** brand; "New lease review" and "Report an issue" buttons; divider; the units list (unit id, label, occupancy); "Unassigned" for lease reviews with no unit yet; theme switch at the bottom. On phones it collapses behind a menu button.
- **Unit page `#/u/<unitId>/<tab>`:** header with the unit and occupancy, two tabs: **Issues** (each report: date, photos, work order title + status + severity, or "no work order") and **Lease records** (each lease review: file, status, open items). Rows open the thread. Empty tabs offer the matching action.
- **Threads** open in the main area next to the sidebar; their back link goes to the unit's tab (or Unassigned) instead of "All reviews".
- "Report an issue" opens `#/report/<unitId?>` with the unit picked when you came from a unit. The old start page and its history list go away; home is a short intro that points at the units.
- API: `ConversationSummary.workOrder` (title, status, severity, urgent). The web loads the summary list once and groups it by unit (fine for one owner; a `unitId` filter on the API at scale).

### Results
- **Sidebar layout (Oct 5), written by Claude** (agy-bridge was timing out this session):
  - `App.tsx` is now the shell: `Sidebar` + main area. `useWorkspace` loads units and conversation summaries and reloads them on every route change, so statuses are fresh after leaving a thread. No store: two props were enough.
  - Routes: `#/u/<unitId>/<issues|leases>`, `#/unassigned`, `#/report/<unitId?>`, `#/c/<id>`, `#/`. `threadParent` gives each thread's back link (unit tab, or Unassigned).
  - `UnitPage` (tabs with counts, empty states with the matching action), `IssueReportList`, `LeaseReviewList`, `UnassignedPage`, `ReportPage` (unit picked when you came from a unit), `HomePage`. `startLeaseReview` is shared by the sidebar and the empty state. `StartPage` and its CSS are gone; the theme switch moved to the sidebar footer.
  - API: `ConversationSummary.workOrder` (title, status, severity, urgent).
  - Checked in Chrome (desktop, dark and light): unit tabs, opening a lease thread from a unit, back link, report page prefilled. The phone layout (sidebar folds behind "Menu" under 768 px) is written but not seen: the remote browser wouldn't resize.
  - **Unit ID is picked, not typed (Oct 6):** `UnitSelect` (loads `GET /api/units`) replaces the text box when editing Unit ID in the field list and on its card. Server: `isKnownUnit` rejects any other value for a card edit (400 "X is not one of your units") and for the agent's `update_field` (tool error pointing it to `find_unit`). Tests for both; checked in Chrome on a lease-05 review (R7 FAIL → PASS, unit flag resolved).
  - Still open from the list above: occupancy is shown, but "active lease" and "open issues count" per unit, and the lease details on the unit page, wait for the dashboards the owner will spec later.
